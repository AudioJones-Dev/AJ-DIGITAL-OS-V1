# Design System Standard

## Purpose

Define how AJ Digital OS design-system documentation should be written.

## Standard

The design system SHALL document:

- tokens
- typography
- spacing
- color semantics
- elevation
- motion
- component states
- responsive behavior
- accessibility constraints

The design system SHOULD distinguish:

- foundation tokens
- component patterns
- layout patterns
- state patterns

## Acceptance Criteria

- A component can be built without inventing token meaning.
- State colors are not used interchangeably with brand colors.
- Accessibility constraints are documented alongside visual rules.
