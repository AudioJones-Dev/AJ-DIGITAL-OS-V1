# Screen Acceptance Criteria

## Purpose

Define the baseline acceptance criteria for every major screen.

## Criteria

Every major screen SHALL have:

- a clear primary task
- visible tenant context when relevant
- visible role constraints when relevant
- loading state
- empty state
- error state
- permission-denied state
- partial-success state when partial success is possible
- agent-active or automation-active state when agents can act there
- audit or approval behavior when client impact exists

## Acceptance Criteria

- The screen spec can be reviewed for completeness before implementation.
- No major screen ships without state coverage.
