# Knowledge: Business Memory Pilot KPIs

## Purpose

This note preserves the Business Memory pilot evaluation model without expanding the Cognitive Operating System architecture.

The purpose is not to build a dashboard, create metrics infrastructure, or optimize measurement. The purpose is to define how the first 30-day pilot will be evaluated with minimal process overhead.

## Scope

Active pilot measurement is limited to three KPIs:

1. Decision Support Rate.
2. Rediscovery Rate.
3. Explanatory Power Index.

All other metrics in this note are candidate future metrics. They are not active, not ratified, and not part of the 30-day pilot evaluation.

## Active Pilot KPI 1: Decision Support Rate

### Definition

Percentage of meaningful decisions that explicitly referenced Business Memory.

### Measurement Protocol

- Count meaningful decisions made during the pilot.
- Count decisions that cited Business Memory.
- Record numerator, denominator, and examples.
- Review weekly.

### Evidence Required

- Decision references.
- Business Memory links.
- Brief note describing how Business Memory affected the decision.

### Success Threshold

Propose only after at least one week of use. Do not ratify during initial setup.

### Recording Format

```txt
Week:
Meaningful decisions:
Decisions citing Business Memory:
Decision Support Rate:
Examples:
Notes:
```

## Active Pilot KPI 2: Rediscovery Rate

### Definition

How often an insight was rediscovered even though it already existed in Business Memory.

### Measurement Protocol

Every rediscovery must record:

- date
- question
- existing note
- why retrieval failed

Success means rediscovery trends downward.

### Evidence Required

- Existing Business Memory note.
- Question or decision where the note should have been retrieved.
- Short explanation of the retrieval failure.

### Success Threshold

Propose only after repeated use. Do not ratify during initial setup.

### Recording Format

```txt
Date:
Question:
Existing note:
Why retrieval failed:
Prevention note:
```

## Active Pilot KPI 3: Explanatory Power Index (Working)

### Definition

Working score describing how broadly a principle improves downstream understanding.

### Measurement Protocol

Evaluate each candidate principle qualitatively across:

- Brand
- Sales
- Marketing
- Product
- Documentation
- Architecture
- AI behavior
- Client delivery

Use qualitative scoring only during the pilot.

Do not create a dashboard.

Do not create numeric automation.

### Evidence Required

- Candidate principle note.
- Short qualitative assessment by affected domain.
- Examples of decisions, outputs, or systems clarified by the principle.

### Success Threshold

Propose only after several candidate principles have been tested. Do not ratify during the pilot setup.

### Recording Format

```txt
Principle:
Brand:
Sales:
Marketing:
Product:
Documentation:
Architecture:
AI behavior:
Client delivery:
Summary:
```

## Candidate Future Metrics

The following metrics are preserved as candidate future metrics only.

They are not active.

They are not part of pilot evaluation.

They should not be used to create dashboards or metrics infrastructure during the 30-day pilot.

| Metric | Candidate Purpose |
| --- | --- |
| Knowledge ROI | Compare important decisions improved against new notes created. |
| Evidence Coverage | Track percentage of knowledge or principles with supporting evidence. |
| Retrieval Success Rate | Track whether retrieved notes answered the question. |
| Principle Yield | Track movement from observations to patterns, knowledge, principles, and doctrine. |
| Contradiction Resolution | Track unresolved conflicts and monthly resolution. |
| Decision Reversal Rate | Track decisions later reversed due to missing or ignored knowledge. |
| Doctrine Stability | Track whether ratified doctrine remains useful over time. |
| Average Retrieval Time | Track time required to locate needed knowledge. |
| Framework Creation Rate | Track frameworks derived from principles. |
| Learning Velocity | Track how quickly feedback becomes revised knowledge. |
| Knowledge Quality | Track evidence, traceability, confidence, contradiction, and survival signals. |
| Business Impact | Track revenue, hours saved, product influence, marketing influence, sales influence, and architecture influence. |
| Cognitive Health | Track open questions, assumptions, unknowns, hypotheses, and contradictions. |
| Reality Compression Ratio | Study how much reusable understanding is generated from raw experience. |
| Cognitive Leverage Ratio | Study how much downstream value is created from a single insight. |

## Cognitive Leverage Ratio (Research Idea)

Cognitive Leverage Ratio is a working name for a future metric that asks how much downstream value is created from a single insight.

A single Business Memory note might eventually:

- influence a sales conversation
- become a content idea
- evolve into a framework
- shape a product feature
- inform an AI prompt
- prevent a repeated mistake

This should not be scored during the 30-day pilot. Preserve it only as a research idea.

## End Note

The purpose of this pilot is not to optimize metrics.

The purpose is to determine whether Business Memory improves retrieval, judgment, and decision quality with minimal process overhead.

If the pilot succeeds, KPI architecture may be expanded later.
